# 前端开发手册

本文档说明当前 `frontend` 的代码结构、核心数据流，以及后续修改功能时应该优先查看哪些文件。

## 1. 技术栈

- 构建工具：Vite
- UI 框架：React + MUI
- 全局状态：Zustand
- 3D 工件示意：Three.js
- 曲线图：ECharts
- Unity 集成：直接加载 Unity WebGL build，并通过 `SendMessage` / window event 通信

## 2. 目录结构

```text
frontend/src
  app/                 全局类型、常量、主题
  components/ui/       可复用的小 UI 组件
  features/navigation/ 左侧工艺导航
  features/preview/    Unity 预览、工件示意、悬浮工具条
  features/properties/ 右侧属性面板
  features/tasks/      右侧任务流面板
  store/               Zustand 全局业务状态
  utils/               解析、计算、数值处理等纯函数
```

当前最重要的文件是：

- `src/store/machiningStore.ts`：业务状态和流程动作的中心。
- `src/app/types.ts`：表单、任务步骤、Unity 命令、刚度点等类型定义。
- `src/app/constants.ts`：默认参数、示例参数、材料/刀具库、左侧导航树。
- `src/features/properties/PropertiesPanel.tsx`：根据左侧导航显示不同属性输入页。
- `src/features/tasks/TasksPanel.tsx`：任务流步骤、主按钮行为、上传刚度入口。
- `src/features/preview/UnityWebGLPreview.tsx`：Unity WebGL 加载和前后端通信桥。

## 3. 核心数据流

### 3.1 参数输入

用户在 `PropertiesPanel` 中输入工件、材料、刀具、工艺参数。所有字段都写入 `machiningStore`：

- 工件：`workpiece`
- 材料：`material`
- 刀具：`toolParams`
- 工艺：`processParams`

这些字段在前端表单里都保存为 `string`。真正需要计算或提交接口时，再通过 `utils/number.ts` 和 `utils/workpiece.ts` 转成数值。

### 3.2 任务流

任务流步骤类型在 `src/app/types.ts`：

```ts
export type DemoStep =
  | "PARAM_INPUT"
  | "SCENE_READY"
  | "STIFFNESS_INPUT"
  | "WALL_ERROR_PREDICTION"
  | "MATERIAL_REMOVAL_PREVIEW"
  | "COMPENSATION_DONE"
  | "RESET";
```

主流程由 `machiningStore.runPrimaryAction()` 分发：

1. `PARAM_INPUT` / `RESET`：调用 `runGenerateScene()`，校验工件、材料、刀具、工艺参数，然后向 Unity 发送 `LOAD_WORKPIECE_AND_TOOL`。
2. `STIFFNESS_INPUT`：任务面板主按钮先打开刚度矩阵文件上传。
3. 刚度上传成功后：再次点击主按钮，调用 `runErrorPrediction()`，向后端 `/prediction/wall-error` 请求真实壁厚误差。
4. `WALL_ERROR_PREDICTION`：后端返回带坐标和 `error` 的 `keyPoints` 后，再点击主按钮调用 `runMaterialRemovalPreview()`。
5. `MATERIAL_REMOVAL_PREVIEW`：前端将误差点坐标做 Unity 坐标变换后，通过 `START_MATERIAL_REMOVAL_PREVIEW` 发送给 Unity。
6. Unity 预览完成：通过 window event 通知前端，`markMaterialRemovalPreviewCompleted()` 将预览任务置为完成。
7. `MATERIAL_REMOVAL_PREVIEW` 完成后：主按钮进入补偿建议阶段，调用 `runCompensationPlan()`。

### 3.3 Unity 通信

Unity 命令类型在 `src/app/types.ts`：

```ts
export type UnityCommandType =
  | "LOAD_WORKPIECE_AND_TOOL"
  | "START_MATERIAL_REMOVAL_PREVIEW"
  | "RESET_TO_INITIAL_SCENE";
```

前端发送命令：

- `machiningStore.ts` 中写入 `unityCommand`
- `UnityWebGLPreview.tsx` 监听 `unityCommand`
- 通过 `unityInstance.SendMessage("FrontendBridge", methodName)` 发送给 Unity

命令映射在 `UnityWebGLPreview.tsx`：

```ts
const UNITY_COMMAND_METHODS = {
  LOAD_WORKPIECE_AND_TOOL: "LoadWorkpieceAndTool",
  START_MATERIAL_REMOVAL_PREVIEW: "StartMaterialRemovalPreview",
  RESET_TO_INITIAL_SCENE: "ResetToInitialScene",
};
```

Unity 回传材料去除预览完成：

- Unity 侧触发 `UnityMaterialRemovalPreviewCompleted`
- `UnityWebGLPreview.tsx` 监听该事件
- 调用 `machiningStore.markMaterialRemovalPreviewCompleted()`

### 3.4 刚度数据

刚度文件上传入口有两个，但共用同一份 store 状态：

- `PropertiesPanel.tsx`：左侧导航选中“刚度测点”时的上传按钮。
- `TasksPanel.tsx`：任务流中的“上传刚度测点”主按钮。

统一入口：

- `machiningStore.importStiffnessFile(file)`

解析器：

- `utils/stiffnessParser.ts`

当前刚度文件只记录刚度矩阵，不再记录坐标。每一行是 K 方向测点，空行分隔 I 方向的不同二维矩阵。

支持格式：

```csv
266.9,464.8,543.6,529.9,427.4,213.8
```

多行表示一个二维矩阵的多条 J 行：

```csv
120,118,116
110,108,106
```

多个二维矩阵之间用空行分隔。前端会按 `K{k}_J{j}_I{i}` 自动生成点 id，并只把 `id` 和 `stiffness` 传给后端；后端根据工件尺寸和矩阵索引补齐 `x/y/z`。

解析后写入：

- `keyPoints: KeyPoint[]`
- `stiffnessFile: File | null`

### 3.5 壁厚误差和补偿

当前有两类计算：

- 后端真实预测：`/prediction/wall-error` 根据刚度矩阵、工件、刀具和工艺参数返回壁厚误差。
- 前端补偿 fallback：补偿接口不可用时，仍可用本地公式生成临时补偿建议。

相关文件：

- `utils/compensation.ts`：`calculateLocalSuggestion()`，生成本地补偿建议 fallback。
- `store/machiningStore.ts`：
  - `runErrorPrediction()`：POST `/prediction/wall-error`
  - `runCompensationPlan()`：预留 POST `/compensation/suggest`
- `components/ui/ErrorCurveChart.tsx`：显示误差曲线和补偿线。

当前前端不再为壁厚误差预测做本地 fallback；预测失败时会停在预测步骤，等待重新预测。

## 5. 开发注意事项

1. 表单字段尽量保持 `string`，到校验、计算或接口提交时再转成 number。
2. 业务状态优先放在 `machiningStore.ts`，不要在多个组件里复制流程状态。
3. 属性面板只负责“展示当前节点对应的输入页”，任务推进逻辑尽量放在 store。
4. Unity 命令要通过 `unityCommand.id` 递增触发，避免同一个命令对象被 React 忽略。
5. 刚度文件上传入口可以有多个，但解析和状态写入必须走 `importStiffnessFile()`。
6. 后端接口没接通时，`prediction.ts` 和 `compensation.ts` 是前端 fallback，不应当被当成最终工程算法。
7. 修改任务流时，必须同时检查 `TasksPanel` 的视觉状态和 `machiningStore` 的实际状态迁移。
8. 新增接口字段时，先改 `types.ts`，再改 store 的 payload，最后改 UI。
