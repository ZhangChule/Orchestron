# 后端开发手册

本文档说明当前 `backend` 的代码结构、核心数据流，以及后续修改某个功能时应该优先查看哪些文件。

## 1. 技术栈

- Web 框架：FastAPI
- API 数据校验：Pydantic v2
- 数值计算：NumPy、SciPy
- 服务启动：Uvicorn
- 算法组织：按“接口层 -> 服务编排层 -> 算法模块层”拆分

启动方式：

```bash
cd backend
uvicorn app.main:app --reload --port 8000
```

## 2. 目录结构

```text
backend
  app/
    main.py                         FastAPI 应用入口、CORS、路由注册
    api/
      router.py                     总路由聚合
      routes/                       具体接口路径
    schemas/                        API 请求/响应数据结构
    services/                       业务流程编排
    algorithms/                     算法模块
      cutting_force/                切削力机理模型
      calibration/                  傅里叶级数标定
      solver/                       稳态固定点求解
      error/                        壁厚误差/SLE 求解
      common/                       坐标、矩阵索引等通用算法
    utils/                          调试日志等工具
  requirements.txt                  后端依赖
  mechanistic_force_core.py         静态参考文件，不参与正式流程
  explicit_coupling_model.py        静态参考文件，不参与正式流程
```

当前最重要的文件是：

- `app/main.py`：FastAPI 应用入口。
- `app/api/routes/prediction.py`：壁厚误差预测接口。
- `app/services/prediction_service.py`：预测流程总编排。
- `app/schemas/machining.py`：工件、材料、刀具、工艺、刚度点等共享数据结构。
- `app/schemas/prediction.py`：预测接口请求/响应结构。
- `app/algorithms/cutting_force/mechanistic.py`：切削力机理模型。
- `app/algorithms/calibration/fourier.py`：傅里叶级数标定。
- `app/algorithms/solver/steady_state.py`：稳态固定点求解。
- `app/algorithms/error/wall_error.py`：壁厚误差求解。
- `app/algorithms/common/coordinates.py`：刚度矩阵 id 到工件坐标的映射。

## 3. 核心数据流

### 3.1 壁厚误差预测接口

前端调用：

```text
POST /prediction/wall-error
```

入口文件：

- `app/api/routes/prediction.py`

实际业务编排：

- `app/services/prediction_service.py`

请求结构：

- `WallErrorPredictionRequest`
- 定义在 `app/schemas/prediction.py`

请求中主要包含：

- `workpiece`：工件尺寸
- `material`：材料参数
- `tool`：刀具参数
- `process`：加工参数
- `key_points`：刚度点，目前只包含 `id` 和 `stiffness`
- `model_version`：预测模型版本

### 3.2 刚度矩阵坐标映射

前端上传刚度文件后，只给后端传：

```json
{
  "id": "K1_J1_I1",
  "stiffness": 266.9
}
```

后端在 `app/algorithms/common/coordinates.py` 里解析 id：

- `parse_matrix_point_id()`：解析 `K{k}_J{j}_I{i}`
- `matrix_shape_from_ids()`：根据全部点 id 推断矩阵维度
- `coordinate_from_matrix_index()`：根据工件尺寸补齐 `x/y/z`

当前约定：

- `K`：沿走刀方向，对应工件 `x`
- `J`：沿壁高方向，对应工件 `z`
- `I`：沿径向多次走刀方向，对应工件 `y`

坐标映射逻辑：

- `x = length * k / (K_count - 1)`
- `z = height - (height - base_height) * j / (J_count - 1)`
- `y = thickness / 2 - i * radial_depth`

如果某个方向只有 1 个点，会使用当前代码里的特殊处理。

### 3.3 算法链路

`prediction_service.predict_wall_error()` 的主流程：

1. 根据名义径向切深 `ae` 生成标定切深：

   ```python
   radial_depth_samples = ae * np.linspace(0.75, 1.25, 5)
   ```

2. 调用 `calibrate_linear_fourier_model()` 完成傅里叶标定。

3. 根据刚度点 id 和工件尺寸补齐每个点的 `x/y/z`。

4. 对每个刚度点调用 `solve_wall_error()`。

5. 返回带 `x/y/z/stiffness/error` 的点集。

算法模块顺序：

```text
mechanistic.py
  -> predict_force_one_revolution()

fourier.py
  -> calibrate_linear_fourier_model()

steady_state.py
  -> solve_steady_state_one_period()

wall_error.py
  -> solve_wall_error()
```

`mechanistic_force_core.py` 和 `explicit_coupling_model.py` 现在只作为静态参考文件，不应该再被正式流程 import。

### 3.4 当前调试日志

后端当前只保留两条预测调试日志，定义在 `app/services/prediction_service.py`：

```python
debug_log("prediction.coordinate_stiffness", coordinate_debug)
debug_log("prediction.wall_errors", [{"id": point.id, "error": point.error} for point in results])
```

输出位置是启动 Uvicorn 的终端。

- `prediction.coordinate_stiffness`：后端解析后的 `id/x/y/z/stiffness`
- `prediction.wall_errors`：最终误差值列表

日志工具在：

- `app/utils/debug.py`

它会把数组和复杂对象做摘要处理，避免大量数值刷屏。

## 4. 修改功能应该看哪里

### 4.1 修改接口路径或新增接口

优先修改：

- `app/api/routes/`：新增或修改具体路由文件。
- `app/api/router.py`：注册新的 router。
- `app/schemas/`：定义请求/响应结构。
- `app/services/`：写业务编排逻辑。

例如新增一个 `/prediction/force` 接口，建议：

1. 新增或修改 `app/schemas/prediction.py`
2. 新增 service 函数到 `app/services/prediction_service.py`
3. 在 `app/api/routes/prediction.py` 添加路由

### 4.2 修改前端传给后端的字段

优先修改：

- `app/schemas/machining.py`：共享输入结构，如 `WorkpieceInput`、`ToolInput`、`ProcessInput`、`KeyPointInput`
- `app/schemas/prediction.py`：预测接口整体 request/response
- `app/services/prediction_service.py`：读取新字段并传入算法

同时要检查前端：

- `frontend/src/app/types.ts`
- `frontend/src/store/machiningStore.ts`

后端字段名目前使用 snake_case，例如 `radial_depth`；前端表单内部使用 camelCase，提交接口时在 store 里转换。

### 4.3 修改刚度矩阵 id 规则

优先修改：

- `app/algorithms/common/coordinates.py`

重点函数：

- `POINT_ID_PATTERN`
- `parse_matrix_point_id()`
- `matrix_shape_from_ids()`

如果前端生成 id 的规则也变了，还要同步修改：

- `frontend/src/utils/stiffnessParser.ts`

### 4.4 修改刚度点坐标映射规则

优先修改：

- `app/algorithms/common/coordinates.py`

重点函数：

- `coordinate_from_matrix_index()`

如果要改变 “K/J/I 分别对应哪个几何方向”，只改这个函数通常就够。但如果返回给 Unity 的坐标变换也要变，前端还要改：

- `frontend/src/store/machiningStore.ts`
- 重点看 `buildUnityPreviewPayload()`

### 4.5 修改切削力机理模型

优先修改：

- `app/algorithms/cutting_force/mechanistic.py`

重点区域：

- `ToolGeometry`
- `ForceCoefficients`
- `CuttingConditions`
- `MechanisticDefaults`
- `engagement_limits()`
- `chip_thickness()`
- `project_to_global()`
- `simulate()`
- `predict_force_one_revolution()`

如果新增刀具参数或工艺参数，需要同步修改：

- `app/schemas/machining.py`
- `app/services/prediction_service.py`

### 4.6 修改傅里叶标定

优先修改：

- `app/algorithms/calibration/fourier.py`

重点函数：

- `trig_fourier_coefficients()`
- `reconstruct_from_trig_coeffs()`
- `calibrate_linear_fourier_model()`
- `force_from_model()`

如果要修改标定切深采样范围，目前入口在：

- `app/services/prediction_service.py`

当前写法：

```python
radial_depth_samples = radial_depth * np.linspace(0.75, 1.25, 5)
```

### 4.7 修改稳态求解

优先修改：

- `app/algorithms/solver/steady_state.py`

重点函数：

- `sdof_from_stiffness()`
- `sdof_derived_params()`
- `f0_f1()`
- `solve_steady_state_one_period()`

如果要改阻尼比、固有频率等默认值，目前在：

- `app/services/prediction_service.py`

当前默认值：

```python
DEFAULT_DAMPING_RATIO = 0.0083
DEFAULT_NATURAL_FREQUENCY_HZ = 60.5
```

### 4.8 修改壁厚误差求解

优先修改：

- `app/algorithms/error/wall_error.py`

重点函数：

- `local_surface_trace()`
- `local_sle_from_periodic_orbit()`
- `solve_wall_error_with_response()`
- `solve_wall_error()`

如果误差定义从当前 SLE 公式变成别的指标，优先改这里。

### 4.9 修改补偿建议

优先修改：

- `app/api/routes/compensation.py`
- `app/schemas/compensation.py`
- `app/services/compensation_service.py`

当前补偿接口：

```text
POST /compensation/suggest
```

当前仍是比较轻量的后端计算。后续如果要接入真实补偿算法，可以从 `compensation_service.py` 拆到新的算法模块，例如：

```text
app/algorithms/compensation/
```

### 4.10 修改调试日志

优先修改：

- `app/services/prediction_service.py`
- `app/utils/debug.py`

如果只是增删预测流程中的日志，通常改 `prediction_service.py` 即可。

如果要改变日志格式、数组摘要方式、是否完整输出数组，改 `debug.py`。

### 4.11 修改 CORS 或后端启动配置

优先修改：

- `app/main.py`

当前允许的前端地址：

```python
allow_origins=[
    "http://localhost:5173",
    "http://127.0.0.1:5173",
]
```

如果前端端口变了，或者部署到其他域名，需要在这里加 origin。

## 5. 开发注意事项

1. `mechanistic_force_core.py` 和 `explicit_coupling_model.py` 只做静态参考，不要在正式流程里 import。
2. API schema 用 Pydantic 管住边界，算法模块里尽量使用普通 dataclass 和 NumPy 数组。
3. 服务层负责“组织流程”，算法层负责“纯计算”，不要把 FastAPI 请求对象传进算法模块。
4. 刚度文件的坐标补齐逻辑集中放在 `coordinates.py`，不要散落在 service 或算法函数里。
5. 调试日志尽量放在 service 层，算法中间量很大，默认不要长期开启。
6. 修改后端字段时，要同步检查前端 payload，否则接口会 422。
7. 数值算法改动后，至少跑一次 `python -m compileall backend`，再用小刚度矩阵跑完整预测链路。
